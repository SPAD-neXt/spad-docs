# Device UI options

Options in the device description that lay out the device page SPAD.neXt generates for a device.

:::info
The options on this page are new in SPAD.neXt 27. Earlier versions ignore them.
:::

## Overview

| Option | Set on | Purpose |
| --- | --- | --- |
| `UI.GROUP` | input | Puts the input into a named group of its sub panel |
| `UI.GROUPS` | device | Order of the groups |
| `PANEL.<panel>.UI.GROUPS` | device | Order of the groups of one sub panel |
| `UI.GROUP.<group>.DOCK` | device | Where a group stands |
| `UI.GROUP.<group>.ORIENTATION` | device | How the inputs inside a group are arranged |
| `CUSTOM_TYPE` = `HAT` | input | Shows the input as a hat switch |

## Groups

Groups split a sub panel into framed boxes with a title, for example *Buttons*, *Axes* and *Hat switches* side by side.

- **`UI.GROUP`** (input): the name of the group. The name is the title of the box; a resource `<RESOURCE_KEY><group>` translates it.
- **Inputs without `UI.GROUP`** stay outside the groups.
- **`UI.GROUPS`** (device) or **`PANEL.<panel>.UI.GROUPS`** (device, for one sub panel): comma-separated list of the group names. Groups not in the list follow in the order their first input appears.
- **`UI.GROUP.<group>.DOCK`** (device): where the group stands.
  - `Left` (default), `Right`, `Top`, `Bottom`: the group stands at that side of the remaining space. Groups earlier in the order are placed first, so the first group with `Right` is the outermost one on the right.
  - `Fill`: the group takes the space that is left and scrolls when its inputs do not fit. It is always placed last.
- **`UI.GROUP.<group>.ORIENTATION`** (device): `Horizontal` (default) lets the inputs wrap from left to right; `Vertical` puts them one below the other.

### Example

Buttons fill the page, axes and hat switches stand on the right, as on the joystick page:

```xml
<Option Key="UI.GROUPS" Value="HatSwitches,Axes,Buttons" />
<Option Key="UI.GROUP.HatSwitches.DOCK" Value="Right" />
<Option Key="UI.GROUP.HatSwitches.ORIENTATION" Value="Vertical" />
<Option Key="UI.GROUP.Axes.DOCK" Value="Right" />
<Option Key="UI.GROUP.Axes.ORIENTATION" Value="Vertical" />
<Option Key="UI.GROUP.Buttons.DOCK" Value="Fill" />

<Input Type="PUSHBUTTON" Tag="BUTTON_1">
  <Option Key="UI.GROUP" Value="Buttons" />
</Input>
<Input Type="AXIS" Tag="X_AXIS">
  <Option Key="UI.GROUP" Value="Axes" />
</Input>
```

## Hat switch

An input with `UI.TYPE` = `3` and `CUSTOM_TYPE` = `HAT` is shown as a hat switch. The arrow of the current direction lights up.

- The input needs `HATSWITCH_POV_COUNT`: SPAD.neXt then creates its direction inputs `<tag>_POV_NORTH`, `<tag>_POV_NORTHEAST`, `<tag>_POV_EAST`, `<tag>_POV_SOUTHEAST`, `<tag>_POV_SOUTH`, `<tag>_POV_SOUTHWEST`, `<tag>_POV_WEST` and `<tag>_POV_NORTHWEST`.
- A pressed direction is shown; when it is released the hat shows the centre.
- Size: `Width` and `Height` of the input, default 70 x 70.

```xml
<Input Type="PUSHBUTTON" Tag="HATSWITCH_0">
  <Option Key="HATSWITCH_POV_COUNT" Value="8" />
  <Option Key="UI.TYPE" Value="3" />
  <Option Key="CUSTOM_TYPE" Value="HAT" />
</Input>
```
